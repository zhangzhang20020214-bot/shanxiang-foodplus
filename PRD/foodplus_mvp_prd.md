# 膳享+（FoodPlus）MVP 产品需求文档（PRD）

> 版本：v1.0 · 文档用途：直接交付 Claude Code 进行前端网页实现
> 项目代号：foodplus-mvp

---

## 0. 给 Claude Code 的阅读说明

- 本系统是一个「多模态识别 + 健康档案」驱动的饮食决策 Agent 网页应用。
- **前端只负责：采集输入（图片/文本/摄像头）、渲染结果、管理档案、交互流转。**
- **所有业务判断（风险拦截、膳食建议、合规校验、结构化输出）均在 Dify Agent 侧完成。** 前端不实现任何营养/医学判断逻辑。
- MVP 仅做网页端，浏览器调用摄像头，**不做原生 App**。
- 页面需同时适配手机与电脑（响应式设计），详见第 4 节。
- 开发时请先搭建「档案模块 → 首页 5 大功能入口 → 对话/历史 → 个人中心」的主干骨架，再接 Dify 接口。

## 1. 产品概述

### 1.1 项目名称
**膳享+（FoodPlus）**

### 1.2 一句话定位
基于「多模态识别 + 个人健康档案」的饮食决策 Agent：用户拍一张照片或输入一句话，系统结合健康档案给出安全、可执行、合规的饮食建议。

### 1.3 项目目标
1. 提供一个网页 MVP，让用户通过手机/电脑浏览器即可使用全部核心能力。
2. 打通「图像识别 / 文字输入 → 健康档案 → RAG 膳食知识 → LLM 建议 → 结构化结果」的完整链路。
3. 建立可复用的健康档案体系，支撑个性化的饮食建议。
4. 在安全与合规前提下（高危食材拦截、禁止医疗诊断、强制免责声明）给出可信赖的膳食建议。

### 1.4 核心价值
| 维度 | 价值描述 |
|------|----------|
| **个性化** | 建议基于用户健康档案（年龄/目标/限制/偏好），而非通用模板 |
| **多模态** | 支持「拍冰箱 / 拍餐盘 / 拍菜单 / 拍配料表 / 文字搜菜」五种输入方式 |
| **安全合规** | 前置硬规则拦截高危食材，后置合规校验，强制免责声明，规避医疗风险 |
| **可执行** | 输出结构化 JSON，前端直接渲染出可行动的菜谱、改良方案与进食建议 |

### 1.5 核心用户流程（总览）
```
选择/新建健康档案
        ↓
选择功能入口（拍冰箱/拍餐盘/搜菜品/看菜单/读配料）
        ↓
输入图片或文本 → 调用 Dify Agent（携带当前档案）
        ↓
Agent 前置校验 → RAG 检索 → LLM 生成 → 后置合规校验
        ↓
返回结构化 JSON → 前端渲染建议卡片
        ↓
询问是否保存/更新健康档案
```

## 2. 目标用户

| 用户类型 | 特征 | 核心诉求 | 典型场景 |
|----------|------|----------|----------|
| **慢病管理人群** | 需控糖/控油/控盐/身材管理 | 判断「这顿饭能不能吃、怎么吃」 | 拍餐盘看升糖与油盐风险 |
| **特殊阶段人群** | 孕期/老人/儿童/术后康复 | 规避高危食材，获取针对建议 | 拍配料表检查是否含禁忌成分 |
| **家庭饮食决策者** | 为全家做饭、管理多份档案 | 一人管多份档案，快速切换 | 拍冰箱规划全家伙食 |
| **健康饮食爱好者** | 均衡饮食、改良菜谱 | 获取做法与健康改良方案 | 搜菜品做低油低盐版本 |

## 3. 功能需求

### 3.1 信息架构总览
```
膳享+ Web App
├── 首页（功能模块）
│   ├── 5 个核心功能入口（拍冰箱/拍餐盘/搜菜品/看菜单/读配料）
│   ├── 底部对话输入框
│   ├── 左侧历史记录（电脑）/ 抽屉式历史（手机）
│   └── 分析结果卡片区（渲染结构化 JSON）
├── 档案模块
│   ├── 档案列表（多份：新增/切换/编辑/删除/设为当前）
│   └── 档案详情表单（基础信息/特殊阶段/健康目标/特殊营养/饮食偏好/健康限制）
└── 我（个人中心）
    ├── 用户设置
    └── 免责声明
```

### 3.2 档案模块

#### 3.2.1 功能描述
管理用户健康档案。支持**多份档案的新增、切换、编辑**；系统始终维护一个「当前选中档案」，所有 AI 分析均携带该档案。

#### 3.2.2 档案字段（数据模型）
```jsonc
{
  "id": "profile_uuid",
  "name": "爸爸的档案",            // 档案昵称，便于区分多份
  "createdAt": "ISO8601",
  "updatedAt": "ISO8601",
  "basicInfo": {
    "age": 55,                     // 年龄（数字）
    "gender": "male",              // male | female | other
    "heightCm": 172,               // 身高 cm
    "weightKg": 75                 // 体重 kg
  },
  "specialStage": [                // 特殊阶段（可多选，可空）
    "pregnancy"                    // pregnancy 孕期 | elderly 老人 | child 儿童 | recovery 康复
  ],
  "healthGoals": [                 // 健康目标（可多选）
    "sugar_control",               // 控糖
    "oil_control",                 // 控油
    "salt_control",                // 控盐
    "balanced",                    // 均衡饮食
    "body_management"              // 身材管理
  ],
  "specialNutrition": ["钙", "叶酸"],   // 特殊营养（自由标签/文本）
  "dietaryPreferences": ["清淡", "少辣"], // 饮食偏好（文本标签）
  "healthRestrictions": [          // 健康限制 / 禁忌（可多选）
    {
      "type": "allergy",           // allergy 过敏 | disease 疾病 | drug 用药 | taboo 禁忌
      "item": "花生",              // 具体条目
      "severity": "high"           // high 高危（触发拦截）| medium | low
    }
  ]
}
```

#### 3.2.3 档案操作
| 操作 | 说明 |
|------|------|
| **新增** | 填写表单 → 保存为一份新档案 |
| **切换** | 在档案列表点击某份档案 → 设为「当前选中档案」，全局生效 |
| **编辑** | 修改任意字段，保存后 `updatedAt` 更新 |
| **删除** | 二次确认后删除（当前选中档案被删除后，自动切换到剩余第一份或提示新建） |
| **设为当前** | 顶部/首页展示当前档案名，一键进入切换 |

#### 3.2.4 页面组件
- **档案列表页**：卡片列表，每张卡片展示「档案名 + 关键标签（目标/阶段摘要）」，右上角「＋ 新建档案」按钮。
- **档案编辑页/弹窗**：分组的表单，含「基础信息」「特殊阶段」「健康目标」「特殊营养」「饮食偏好」「健康限制」区块。
- **健康限制编辑**：支持动态增删条目，每项含「类型 / 条目 / 严重程度」。
- **当前档案指示器**：首页顶部常驻显示「当前档案：爸爸的档案 ▾」，点击进入切换。

### 3.3 首页功能模块

#### 3.3.1 功能描述
首页提供 5 个核心功能入口 + 底部对话输入框 + 历史记录 + 结果渲染区。所有入口最终都走同一套「调用 Agent → 渲染 JSON」流程。

#### 3.3.2 五大功能入口

| 入口 | 输入方式 | 功能描述 | 输出 |
|------|----------|----------|------|
| **① 拍冰箱** | 拍照/上传图片 | 识别现有食材，基于当前档案推荐可做的餐食 | 食材清单 + 推荐餐食组合 |
| **② 拍餐盘** | 拍照/上传图片 | 识别菜品并给出进食建议（量、顺序、风险提示） | 菜品识别 + 进食建议 |
| **③ 搜菜品** | 文本输入菜名 | 获取菜肴做法及健康改良方案 | 做法步骤 + 健康改良方案 |
| **④ 看菜单** | 拍照/OCR 菜单 | 识别菜单，推荐适合当前档案的菜品组合 | 菜单识别 + 推荐组合 |
| **⑤ 读配料** | 拍预包装食品 | 识别配料表、营养标签，评估适配度 | 配料/营养成分 + 风险与建议 |

#### 3.3.3 底部对话输入框
- 固定于页面底部（电脑端居中，手机端贴底）。
- 支持：**文本输入 + 图片上传 + 摄像头拍照** 三种输入。
- 输入区含：文本框、📎 上传图片按钮、📷 拍照按钮、发送按钮。
- 发送后进入「分析中」状态（加载态），完成后渲染结果卡片。

#### 3.3.4 历史记录（左侧/抽屉）
- 电脑端：左侧侧边栏展示历史会话列表（按时间倒序）。
- 手机端：通过顶部菜单按钮呼出抽屉。
- 每条历史记录展示「缩略摘要 + 功能类型标签 + 时间」；点击可查看完整历史结果。
- 支持清空历史。

#### 3.3.5 分析结果卡片区
- 渲染 Dify 返回的结构化 JSON（见 3.5）。
- 卡片底部固定出现 **「是否保存/更新健康档案？」** 的询问条，含「保存到档案」/「跳过」两个动作。

#### 3.3.6 页面组件（首页）
- **顶部栏**：Logo「膳享+」、当前档案指示器、菜单按钮（手机）。
- **功能入口网格**：5 个入口卡片，图标 + 名称，点击进入对应输入模式。
- **主内容区**：结果卡片流（上下滚动）。
- **底部输入框**：文本 + 图片 + 拍照 + 发送。
- **历史侧边栏/抽屉**：历史会话列表。

#### 3.4.1 功能描述
用户设置 + 免责声明展示。

#### 3.4.2 页面组件

### 3.5 底层 Agent 逻辑（Dify Agent 契约）

> 前端必须严格遵循以下契约，**不做任何业务判断**。

#### 3.5.1 请求流程
```
1. 输入图片/文本 + 当前选中健康档案（profileId）
2. 前置硬规则校验：高危食材直接拦截 → 输出风险提示（不进入生成）
3. RAG 检索膳食指南知识库
4. LLM 生成饮食建议
5. 后置合规校验：禁止医疗诊断话术、强制附加免责声明
6. 固定返回结构化 JSON
```

#### 3.5.2 前端 → Agent 请求结构（约定）
```jsonc
{
  "profile": { /* 完整档案对象，见 3.2.2 */ },
  "mode": "fridge",            // fridge 拍冰箱 | plate 拍餐盘 | dish 搜菜品 | menu 看菜单 | ingredient 读配料
  "input": {
    "text": "西红柿炒蛋怎么做",  // 文本输入（搜菜品等）
    "images": ["data:image/jpeg;base64,..."] // 图片输入（可多张）
  }
}
```

#### 3.5.3 Agent → 前端 结构化返回（约定 JSON Schema）
```jsonc
{
  "blocked": false,              // true 表示被前置硬规则拦截
  "risk": {                      // blocked=true 时返回
    "level": "high",             // high | medium | low
    "message": "检测到花生，与档案过敏项冲突，已拦截",
    "items": ["花生"]
  },
  "result": {                    // blocked=false 时返回
    "mode": "fridge",
    "title": "推荐餐食建议",
    "ingredients": [             // 拍冰箱：识别到的食材
      { "name": "鸡蛋", "category": "蛋白质", "note": "" }
    ],
    "dishes": [                  // 识别菜品 / 推荐餐食 / 菜单组合
      {
        "name": "番茄炒蛋",
        "reason": "低油低盐，符合控盐目标",
        "recipe": [ "打蛋", "热锅少油", "翻炒" ],
        "healthModification": "用橄榄油替代，减盐 30%",
        "suitable": true
      }
    ],
    "nutrition": {               // 读配料：营养标签识别
      "ingredients": ["水", "白砂糖", "..."],
      "labels": { "热量": "180kJ", "钠": "120mg" },
      "riskItems": ["白砂糖"]
    },
    "advice": [                  // 进食建议 / 通用建议（要点列表）
      "建议先吃蔬菜再吃主食",
      "本餐油盐偏高，建议减少主食量"
    ],
    "disclaimer": "本建议仅供参考，不构成医疗诊断或治疗意见。如有健康问题请咨询专业医生。"
  }
}
```

#### 3.5.4 前端渲染规则
- `blocked === true` → 渲染红色风险提示卡，展示 `risk.message`。
- `blocked === false` → 按 `result` 各字段渲染对应卡片（食材/菜品/营养/建议/免责声明）。
- **免责声明文案必须随每次结果强制展示**，不得省略。
- 前端不自行解释、不追加任何医疗/营养结论。

## 4. 非功能性需求

### 4.1 响应式设计（核心非功能要求）
网页需同时适配 **手机与电脑**，采用「移动优先 + 断点增强」策略。

| 断点 | 范围 | 布局 |
|------|------|------|
| **手机（< 768px）** | 主流手机竖屏 | 单列布局；功能入口 2 列网格；历史记录改为抽屉；底部输入框贴底；顶部栏精简 |
| **平板（768–1024px）** | 平板 | 功能入口 3 列网格；历史侧边栏可收起 |
| **电脑（> 1024px）** | 桌面浏览器 | 三栏布局：左侧历史侧边栏 + 中间结果区 + 右侧（可选）档案快捷信息；底部输入框居中限宽 |

响应式要点：
- 使用 CSS Grid / Flexbox + 媒体查询（或 Tailwind 断点）实现。
- 功能入口卡片：手机 2 列、平板 3 列、电脑 5 列（或 5 列横排）。
- 底部输入框：电脑端居中、限制最大宽度（如 720px）。
- 历史记录：电脑常驻左侧栏，手机收进抽屉（汉堡菜单呼出）。
- 触控友好：手机端按钮最小点击区域 ≥ 44px。

### 4.2 摄像头调用（浏览器）
- 使用 `navigator.mediaDevices.getUserMedia` 调用摄像头拍照。
- 需处理：用户拒绝授权、非 HTTPS/localhost 环境不可用、无摄像头设备等降级场景（提示改用上传图片）。
- 生产环境必须 HTTPS（浏览器安全策略要求）。

### 4.3 其他非功能要求
| 类别 | 要求 |
|------|------|
| **技术栈建议** | 前端：React / Vue（推荐 React + TypeScript）+ Tailwind CSS；如需可上 Next.js |
| **浏览器兼容** | Chrome / Safari / Edge 最近两个大版本；移动端 iOS Safari / Android Chrome |
| **性能** | 首屏加载 < 3s；图片上传前做前端压缩（限制体积，如 ≤ 4MB） |
| **状态管理** | 当前选中档案需全局状态管理，切换后全局联动 |
| **数据存储** | MVP 阶段档案与历史记录可用浏览器 localStorage 持久化；后续再接后端 |
| **接口对接** | Dify Agent 接口统一封装为一个 service 层，前端所有功能入口复用 |
| **安全** | 前端不做医疗判断；不落盘敏感健康数据到第三方（除非产品另行约定） |
| **可访问性** | 图片按钮提供 alt/aria-label；表单提供 label；对比度满足基本可读性 |

## 5. MVP 范围与里程碑（建议）

### 5.1 MVP 范围内（本期做）
- ✅ 档案模块：多份档案增删改查、切换、设为当前。
- ✅ 首页 5 大功能入口 + 底部对话输入框 + 历史记录。
- ✅ 结果卡片渲染（对接 Dify 结构化 JSON）。
- ✅ 个人中心：用户设置 + 免责声明。
- ✅ 响应式（手机 + 电脑）。

### 5.2 MVP 范围外（本期不做）
- ❌ 原生 App。
- ❌ 后端用户账号/云端档案同步（先用 localStorage）。
- ❌ 复杂营养数据库/自定义知识库管理后台。
- ❌ 支付/会员/社交等。

## 6. 术语表
| 术语 | 说明 |
|------|------|
| **当前选中档案** | 全局生效的那份健康档案，所有 AI 分析都携带它 |
| **前置硬规则** | Agent 在生成前对高危食材（过敏/禁忌）的硬性拦截 |
| **后置合规** | Agent 生成后对医疗诊断话术的校验与免责声明强制附加 |
| **RAG** | 检索增强生成，从膳食指南知识库检索后生成建议 |
| **结构化 JSON** | Agent 固定格式输出，前端据此渲染 |
